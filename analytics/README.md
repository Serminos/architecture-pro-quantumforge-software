# Задание 7. Аналитика покрытия и качества базы знаний

## Описание

В этом задании мы оцениваем полноту и актуальность базы знаний, выявляем темы, по которым бот не может дать ответы, и обоснованно улучшаем покрытие. Это ключевой шаг, чтобы превратить RAG-бота из эксперимента в полноценный рабочий инструмент.

Цель: оценить качество RAG-системы, найти пробелы в покрытии, выявить склонность к галлюцинациям и предложить конкретные улучшения базы знаний.

## Структура папки `analytics/`

```
analytics/
├── create_golden_set.py      # Создание золотого набора и искусственных пробелов
├── test_rag_bot.py           # Автоматическое тестирование на золотом наборе
├── analyze_results.py        # Анализ логов и генерация отчёта
├── golden_questions.json     # Золотой набор вопросов (создаётся)
├── logs.jsonl                # Логи тестирования (создаётся)
├── coverage_report.md        # Отчёт о покрытии (создаётся)
└── README.md                 # Этот файл
```

## Как работает процесс

1. Создание золотого набора (`create_golden_set.py`):
   - Генерирует `golden_questions.json` с 13 вопросами (8 известных, 5 удалённых/отсутствующих).
   - Физически удаляет 3 файла из `knowledge_base/final/` (создаёт искусственные пробелы) и сохраняет их бэкап.
   - Важно: после удаления файлов нужно перестроить индекс!

2. Тестирование (`test_rag_bot.py`):
   - Загружает индекс и золотой набор.
   - Для каждого вопроса выполняет поиск и генерацию ответа.
   - Логирует результат в `logs.jsonl`.

3. Анализ и отчёт (`analyze_results.py`):
   - Читает логи, вычисляет метрики.
   - Генерирует `coverage_report.md` с выводами.

## Запуск

```bash
# 1. Перейти в папку analytics
cd analytics

# 2. Создать золотой набор и удалить файлы (один раз)
python create_golden_set.py

# 3. Перестроить индекс (обязательно!)
cd ../vector_index
python build_index.py

# 4. Вернуться и запустить тестирование
cd ../analytics
python test_rag_bot.py

# 5. Проанализировать результаты
python analyze_results.py
```

| Категория     | Всего | Успешно | Должны ответить |

Интерпретация:

- Технологии (`technologies`)  также слабое место: 1 из 3. Описание `Zvezda Smerti` слишком поверхностное.

- Планеты и события  на среднем уровне (50%).

### ⚠️ Пробелы в покрытии

- Нет вопросов без чанков  все запросы находят хотя бы один документ. Это хорошо, значит база не пуста.
- Низкое качество ответов:
  - `Кто такой Semyon Tyomnov?`  найдено только 1 из 4 ключевых слов.
  - `Что такое Zvezda Smerti?`  найдено только 1 из 4 ключевых слов.
- Утечка/галлюцинация:
  - `Кто такой Starik Vseslavov?`  бот дал ответ, хотя должен был отказаться (удалённый персонаж). Причина: имя встречается в других документах (кросс-референсы).

### 💡 Рекомендации по улучшению

#### 1. Расширить базу знаний (добавить контент)
- Semyon Tyomnov  добавить больше описания: его роль, происхождение, ключевые события.
- Zvezda Smerti  дополнить техническими характеристиками, историей создания и уничтожения.
- Starik Vseslavov  если персонаж удалён намеренно, нужно либо удалить все упоминания во всех файлах, либо усилить pre-prompt, чтобы модель игнорировала запросы о нём.

#### 2. Увеличить `TOP_K` в поиске
Сейчас `TOP_K = 5`. Увеличение до 10 повысит шанс найти релевантные чанки, особенно для запросов с малым количеством точных совпадений.

#### 3. Усилить pre‑prompt (защита от галлюцинаций)
В системный промпт добавить явный список удалённых сущностей и инструкцию игнорировать вопросы о них.

#### 4. Внедрить пост‑фильтрацию ответов
Проверять, найден ли хотя бы один чанк с основной сущностью. Если нет  принудительно отвечать «Я не знаю».

#### 5. Пересмотреть стратегию удаления
Для тестов на «пробелы» лучше использовать не физическое удаление файлов, а добавление метаданных `deprecated: true` и фильтрацию при поиске. Это позволяет контролировать доступ к информации без нарушения связности текстов.
